## Purpose

This folder contains the Phase 1 Waterfall discovery and requirements baseline
for Raihan's OS. Phase 1 produces documentation only. It does not authorize
implementation, deployment, or public release.

The package is based on:

- structured Product Owner interviews;
- the earlier project conversation about a personal research lab, Research OS,
  negative results, and research lineage;
- a preliminary benchmark of OS-style portfolios and interactive research
  publications;
- W3C accessibility guidance, Google Search documentation, Core Web Vitals,
  OWASP guidance, MDX documentation, SPDX licensing guidance, and the
  Rei Quantitative Research Protocol.

## Product decision hierarchy

When trade-offs cannot be avoided, use this order:

1. Quality and rigor
2. Visual experience
3. Maintainability
4. Originality
5. Speed to launch

Working weights for prioritization are 30%, 25%, 20%, 15%, and 10%
respectively. These weights are a planning mechanism, not a mathematical claim.

## Release model

Raihan's OS will not use a public beta.

1. Build and validate the platform privately.
2. Produce and integrate the first flagship interactive work.
3. Complete the minimum launch content.
4. Run repeated functional, visual, accessibility, performance, security,
   content, and cross-device QC.
5. Launch publicly only as a polished official release.

Platform completion is therefore not the same as public launch readiness.

## Document control

- A requirement is not approved merely because it appears in Draft v0.1.
- Product Owner walkthrough and explicit Phase 1 sign-off are required.
- Changes after sign-off must be recorded in the Decision Log and assessed
  against scope, quality, maintenance, privacy, content, and launch criteria.
- Missing project artifacts are recorded as data gaps; they are never replaced
  with invented claims, metrics, clients, methods, or results.
