# Architecture Decision Records

This folder preserves significant Phase 2 product, design, architecture,
integration, privacy, and operational decisions.

## Status lifecycle

    Proposed → Accepted → Deprecated → Superseded
                      ↘ Rejected

## Rules

- Write an ADR before implementing a significant, costly-to-reverse decision.
- Record context, drivers, considered options, decision, consequences, risks,
  reversibility, and affected requirements.
- Do not rewrite an accepted ADR to hide changed reasoning. Create a new ADR
  that supersedes it.
- Routine copy, spacing, and local implementation details do not require ADRs.
- Raihan is the final decision authority.
